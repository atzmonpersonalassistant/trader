# Earnings Volatility Radar

Rolling scanner for earnings-driven options volatility opportunities.

The scanner rebuilds its universe on every run from:

1. upcoming earnings in the next configurable window, default 7 days;
2. a fixed personal watchlist;
3. local earnings-move history when available.

It is a **radar**, not an auto-trader. The output is a small list of situations worth manual review, not buy/sell instructions.

## What it does

For every ticker in the dynamic universe, it attempts to calculate:

- event status: earnings today, tomorrow, soon, post-earnings review, or watch-only;
- stock price;
- front and back option expiries;
- ATM straddle cost;
- implied/expected move percent;
- historical median/average earnings move from local history;
- front/back IV ratio;
- basic option liquidity score;
- posture classification.

Possible postures:

- `LONG_VOL_CANDIDATE`
- `SHORT_VOL_CANDIDATE`
- `CALENDAR_CANDIDATE`
- `POST_EARNINGS_REVIEW`
- `WATCH_ONLY`
- `NO_EDGE`
- `REJECTED_ILLIQUID`
- `REJECTED_DATA_ERROR`

## Files

- `scan.py` — main scanner.
- `run.sh` — launchd/cron-friendly wrapper.
- `config/earnings.example.csv` — example upcoming earnings calendar.
- `config/watchlist.example.csv` — example permanent watchlist.
- `data/earnings_history.example.csv` — example local earnings-move history.
- `output/` — runtime outputs.

## Setup

Create local editable files:

```bash
cp earnings-volatility-radar/config/earnings.example.csv earnings-volatility-radar/config/earnings.csv
cp earnings-volatility-radar/config/watchlist.example.csv earnings-volatility-radar/config/watchlist.csv
cp earnings-volatility-radar/data/earnings_history.example.csv earnings-volatility-radar/data/earnings_history.csv
```

Later, `config/earnings.csv` should be generated from an earnings-calendar provider. For the MVP it can be maintained manually or generated by a separate job.

## Run manually

From repo root:

```bash
uv run --with yfinance --with pandas python earnings-volatility-radar/scan.py
```

With example data:

```bash
uv run --with yfinance --with pandas python earnings-volatility-radar/scan.py \
  --earnings earnings-volatility-radar/config/earnings.example.csv \
  --watchlist earnings-volatility-radar/config/watchlist.example.csv \
  --history earnings-volatility-radar/data/earnings_history.example.csv
```

For reproducible testing:

```bash
uv run --with yfinance --with pandas python earnings-volatility-radar/scan.py \
  --today 2026-06-01 \
  --earnings earnings-volatility-radar/config/earnings.example.csv \
  --watchlist earnings-volatility-radar/config/watchlist.example.csv \
  --history earnings-volatility-radar/data/earnings_history.example.csv
```

## Outputs

By default, results are written to:

- `earnings-volatility-radar/output/candidates.csv` — latest tabular radar output.
- `earnings-volatility-radar/output/candidates.json` — latest machine-readable radar output.
- `earnings-volatility-radar/output/post_earnings_review.csv` — planned future review artifact.
- `earnings-volatility-radar/output/earnings_volatility_radar.log` — wrapper log when `run.sh` is used with the default log path.

The output directory can be changed with `--output-dir` or `EARNINGS_VOL_RADAR_OUTPUT_DIR`.

If `EARNINGS_VOL_RADAR_WHATSAPP_TARGET` or `--send-whatsapp-to` is set, sendable candidates are sent to the **Options radar** WhatsApp group. If there are no sendable candidates, the script prints `NO_REPLY` and sends nothing.

Runtime outputs are ignored by git except for `output/README.md`.

## Scheduler wrapper

```bash
earnings-volatility-radar/run.sh
```

By default, the wrapper runs only on weekdays, at minutes `05` and `35`, between local hours `16:00-22:00`.

Useful environment variables:

- `EARNINGS_VOL_RADAR_EARNINGS` — path to upcoming earnings CSV.
- `EARNINGS_VOL_RADAR_WATCHLIST` — path to watchlist CSV.
- `EARNINGS_VOL_RADAR_HISTORY` — path to earnings history CSV.
- `EARNINGS_VOL_RADAR_OUTPUT_DIR` — output directory.
- `EARNINGS_VOL_RADAR_LOOKAHEAD_DAYS` — earnings lookahead window, default 7.
- `EARNINGS_VOL_RADAR_WHATSAPP_TARGET` — WhatsApp target for the **Options radar** group.
- `EARNINGS_VOL_RADAR_LOG_FILE` — wrapper log file.
- `EARNINGS_VOL_RADAR_IGNORE_WRAPPER_WINDOW=1` — bypass wrapper time gate.

## Current MVP limitations

- Earnings calendar is CSV-backed. A provider integration should later generate `config/earnings.csv` dynamically.
- Historical move analysis depends on local `data/earnings_history.csv`.
- Post-earnings review is designed but not fully automated yet.
- Yahoo/yfinance option quotes can be delayed, stale, or incomplete. Always verify in broker data before making decisions.

Information only, not investment advice.
